## 一、`C01301/Ability E [page_config_manager.cpp62] configJson_ is empty`

### 结论：**系统侧诊断日志，非本项目缺陷，无法也不应在应用层"修复"**

### 判据

**1. 时机不对**

该日志出现在 `onNewWant` / `onDidForeground` **之后**（20:10:58.296、20:11:17.191），
而不是冷启动的 `onWindowStageCreate` 阶段。

若页面配置真的为空，`windowStage.loadContent('pages/Splash')` 会直接失败、
应用无法显示任何界面。实际应用启动正常、页面正常渲染。

**2. 前一条日志揭示了真实来源**

```
C05405/...pConfigClient  I  [nodict]GetConfigByApp: GetDataShareData return 0 result
C01301/Ability           E  [page_config_manager.cpp62] configJson_ is empty
```

`GetDataShareData return 0 result` 是**跨进程 DataShare 查询未命中**。
`page_config_manager` 是系统 Ability 框架在 `onNewWant` 路径上查询
某个 DataShare 配置（与应用自身页面无关）时的内部组件，
它对空结果打印了这条 E 级日志。

**3. 本项目页面配置正确**

- `entry/src/main/resources/base/profile/main_pages.json`：16 个页面，格式正确
- 打包产物 `entry/build/default/intermediates/res/default/resources/base/profile/main_pages.json`：内容与源一致
- `module.json5` 的 `"pages": "$profile:main_pages"` 正确指向

**4. 反向验证**：向 `main_pages.json` 写入不存在的页面会触发构建期
`Resource Pack Error`（`Error Code: 11211116`），说明该文件确实被工具链严格校验，
不存在"静默为空"的可能。

### 处置

**不修改。** 应用侧无对应开关可关闭该日志，改动反而可能引入新问题。
功能未受影响。

## 二、`C01406/OHOS::RS E Failed to attach property, property is null.`（大量重复）

### 结论：**系统渲染层（Render Service）在文本输入框占位提示刷新时的内部告警**，
### 与业务逻辑无关，但可通过补全输入框样式**降低其触发概率**

### 判据

**1. 触发点明确**

日志顺序（原文）：

```
C03914/AceTextField  I  On change previewText, len:0, index:<private>
C03914/AceTextField  I  addedLen=0, removedLen=0
   ...（重复 5 次）
C01406/OHOS::RS      E  Failed to attach property, property is null.   ×24
```

`previewText` 即占位提示文本。错误**紧跟**在占位提示刷新之后。

**2. 数量吻合**

- `Plan.ets` 有 **5 个 TextInput + 1 个 TextArea = 6 个输入控件**
- 日志中 `On change previewText` 正好 **5 次**（TextArea 走 `placeholderText`，不报 previewText）
- 一次爆发 **24 条** = 6 控件 × 4 属性

**3. 日志 TAG 指明层次**

`C01406/OHOS::RS` = **Render Service**，属系统渲染进程（native 层），
不在 ArkTS 应用代码内。错误信息 "property is null" 指渲染节点属性未就绪。

**4. 触发条件**

三次爆发（20:10:58.380、20:11:10.810、20:11:22.686）**全部发生在
`onNewWant` 回到前台后重建界面时** —— 即输入框从"不可见"重新变为"可见"、
占位提示需要重新挂载渲染属性的时刻。

### 处置

**已做**：为 7 个生成页的 TextInput/TextArea **补全显式样式**
（`backgroundColor`、`placeholderColor`、`caretColor`、`borderRadius`），
让渲染节点在创建时就有完整属性，减少"属性未就绪"窗口。

**说明**：这是**缓解措施**，不能保证彻底消除 ——
该告警产生于系统渲染层，应用层无法完全控制其时机。
它**不影响功能**（输入、生成、显示均正常），属可忽略的诊断噪音。
