# Rev TechingMaster 云端部署

> 面向：把 AI 中转代理服务部署/迁移到云服务器的完整方案。
> 现状：服务已在线运行于 `https://rev-on.site:3000/health`（200），走 PM2 + 内置 HTTPS + 公网域名的既有部署（详见 `AI部署手册.md`）。
> 本项目 App 端功能改动（多轮对话/人设/压缩包分享）均为客户端逻辑，**无需改动服务端**；部署本服务的目的是让 App 仍可请求到 AI 代理，去掉重复的容器化/可复现方案。

## 1. 有哪些服务在跑（两种形态二选一）

| 形态 | 进程 | 运维方式 | 适合 |
|------|------|----------|------|
| 既有部署（在跑） | PM2 `rev-server` | `pm2 restart rev-server`、scp 覆盖 `src/*.js` | 现网稳定，改动小 |
| 容器化（可选） | Docker `rev-techingmaster-ai` | `bash deploy.sh`、`docker compose` | 可复现、可回滚、依赖隔离 |

两者都监听 `3000` 端口（HTTPS，内置 TLS）。**不要同时开启**，否则端口冲突。

## 3. 从 PM2 迁移到 Docker（可选，需你在现网确认后执行）

> 迁移会**短暂中断服务**且属于生产环境变更，切勿在无人确认时执行。步骤如下：

```bash
cd /opt/rev-server
# ① 先停掉占用 3000 的 PM2 进程，释放端口
pm2 stop rev-server && pm2 save

# ② 确认端口已释放
ss -lntp | grep ':3000' || echo "3000 已空闲"

# ③ 同步新部署文件（Dockerfile / docker-compose.yml / deploy.sh 等）到服务器后
#    （若已在 服务器上则跳过）
bash deploy.sh

# ④ 验证
curl -ksS https://rev-on.site:3000/health
# 期望输出 HTTP 200

# ⑤ 回滚（如需）
docker compose stop rev-techingmaster-ai && pm2 start rev-server
```

| 文件 | 作用 |
|------|------|
