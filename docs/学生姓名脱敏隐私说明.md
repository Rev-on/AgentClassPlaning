# 学生姓名脱敏（Tokenization）隐私保护

> 涉及学生真实姓名的 AI 功能（学情分析、个性化学情报告、沟通话术）在把数据发给
> AI 之前，先把姓名映射为编号（**张三 → S001**），AI 全程只见到编号；
> AI 返回后再把编号还原为真实姓名，用于展示、导出与历史记录。

---

## 1. 一句话说明

```
老师输入：张三 92分，李四 75分
     ↓  脱敏（在手机本地完成）
发给 AI：S001 92分，S002 75分       ← 真实姓名从未离开设备
     ↓  AI 分析
AI 返回：S001 语文基础扎实，S002 需加强阅读
     ↓  还原（在手机本地完成）
老师看到：张三 语文基础扎实，李四 需加强阅读
```

**姓名 ↔ 编号的对照表只存在于本次生成的内存里**：不落盘、不上传、不写日志，生成结束即丢弃。

---

## 2. 覆盖范围

| 功能 | 脱敏对象 | 方式 |
|---|---|---|
| **学情分析**（Analysis） | Excel 表格里的姓名列 | **按列识别**，只替换姓名列 |
| **个性化学情报告**（Report） | 姓名输入框 + 课堂观察记录 | 结构化字段 + 自由文本 |
| **沟通话术**（Talk） | 学生情况描述 + 备注 | 结构识别 + 已知姓名全量替换 |
| **通用层** | 以上所有，且新增功能自动受益 | `NameMask` 服务 |

关键点：这是**通用层**，不是三个页面各写一套。以后新增 AI 功能接入同一服务即可。

---

## 3. 三个原始泄漏点（改造前）

| 位置 | 改造前的写法 | 问题 |
|---|---|---|
| `Analysis.ets` | `${ExcelParser.toJson(rows)}` | JSON 里 `{"姓名":"张三",...}` 原文直发 |
| `Report.ets` | `学生姓名：${this.studentName}` | 原文直发 |
| `Talk.ets` | `学生情况描述：${this.situation}` | 老师手写的姓名原文直发 |

`Prompts.ets` 里 `{学生姓名}` 占位符也已改为 `{学生编号}`，并新增 `anonRule()`
告诉 AI「姓名已用编号替代，请沿用编号称呼」——否则 AI 可能输出"未知学生"或拒答。

## 4. 设计要点

### 4.1 为什么映射表只在内存

- **不落盘**：写进 `preferences` 就等于在设备上留下一份"姓名-编号对照表"，
  一旦设备被他人使用或备份泄露，脱敏形同虚设。
- **不上传**：映射表上传到服务端等于把真名换了个地方存，毫无意义。
- **不写日志**：日志可能被导出、上报、被第三方读取。
  `NameMask.ets` 因此**不 import** `preferences` / `fileIo` / `http` / `HistoryStore` / `PageDraft` / `hilog`
  —— 从根上杜绝这四条泄漏路径（审计脚本会断言这一点）。

### 4.2 Excel 场景为什么必须按列识别

不能对整表做无差别文本替换，否则：

- `等级` 列里的 **"优"、"良"** 会被误改成编号 → AI 收到错误数据；
- `学号` `20250101` 这类数字也可能被误伤；
- 还原后与老师原文对不上。

因此 `maskTable()` 先判定哪些列是姓名列，**只替换命中的列**，其余列逐字节原样拷贝。

姓名列识别：支持 `姓名 / 学生姓名 / 名字 / 学生 / 学员 / 考生姓名 / name / studentName / full_name` 等中英写法（大小写、空格、下划线、全角空格均归一化）。
**排除**：`家长姓名 / 监护人 / 教师姓名 / 班级 / 学号 / 考号 / 序号`
—— 家长姓名不是"学生真实姓名"，且家校沟通需要称呼家长，故不脱敏。

### 4.3 流式还原的坑（重要）

AI 是流式返回的，**编号可能被切成两段**到达：

```
"…S0"   ← 第一片
"01 表现优异…"  ← 第二片
```

如果对每个流式分片单独还原，`S0` 不是合法编号 → 原样保留 → 半个编号永远替换不回来。

**因此：流式期间不还原，只在拿到最终完整文本后统一还原一次。**
（三个页面的流式回调里 `restore()` 调用次数为 0，只有 `push(partial)`。）

### 4.4 fail-closed（宁可失败，也不外发）

出网前有最后一道闸 `NameMask.applyToFlow()`：prompt 里只要**还残留任何已知真实姓名**，
直接抛 `MaskError` 阻断本次生成，界面提示"脱敏校验未通过"。

理由：脱敏是安全属性，一旦失效应当**拒绝服务**而不是"带病运行"把真名发出去。

### 4.5 自由文本的取舍："宁可漏、不可错"

Talk 的描述是自由文本，没有任何标记说明哪个词是人名。

- **做的**：识别高置信结构 —— `张三同学`、`学生姓名：张三`、`张三的妈妈`、`王小明妈妈`。
- **刻意不做的**：无上下文的"2-4 个连续汉字就是姓名"的通用猜测。

因为后者会把 **"成绩下滑"、"家长会"、"单元测试"、"学习方法"、"孩子最近情绪低落"**
整片误改成编号 —— AI 收到的语义直接失真，生成结论是错的，而且还原后与老师原文对不上。
**误改比漏脱敏更糟**：漏脱敏是隐私风险，误改是直接产出错误结果。

兜底：Talk 页新增「学生姓名（选填）」输入框。**填了就一定被编号替换**（无论描述里怎么写）。
描述里手写、又不填姓名框的裸姓名（如"张三和李四都没考好"）仍会外发 —— 这是已知限制。

## 5. 防误伤的具体规则

Talk 页对"人名 + 称谓"的识别有三重边界裁剪（缺一不可）：

| 规则 | 排除的例子 |
|---|---|
| (a) 候选须 2-4 个汉字 | 单字不成名 |
| (b) 候选前不紧邻虚词（的/和/与/给/对/跟…） | "学校的同学"里的"学校" |
| (c) 称谓后不紧跟常见后续字（会/访/们/长/里…） | **"家长会"不被拆成 家长+会** |
| (d) 剥掉候选尾部的领属助词"的" | `李四的妈妈` 只登记 `李四`，不产生 `李四的` 脏数据 |
| (e) 候选本身是称谓/动词则放弃 | "妈妈说"、"家长反映" |

字段标签只保留真正的标签（`学生姓名 / 姓名 / 名字`），且**长标签优先**
—— 否则 `学生姓名：李四` 里短的 `学生` 会抢先命中，把 `姓名` 当成人名。

## 6. 自动化验证

```bash
cd server

# Lead 的独立出口审计：真实姓名有无可能到达网络出口
node tools/audit_name_privacy.js          # 24 项

# Talk 自由文本行为验收：正例脱敏 + 反例逐字不变
node tools/verify_talk_masking.js         # 17 项

# 实现者回归测试：编号/去重/round-trip/表格形状/边界
node tools/test_name_tokenization.js      # 161 项
```

三者合计 **202 项断言**，且相互独立：

- `audit_name_privacy.js` 从**数据流**角度审计（三个泄漏点的 prompt 表达式是否经过脱敏、
  映射表是否只用内存、日志是否可能打印姓名）。
- `verify_talk_masking.js` 从**行为**角度验收（**roles/labels 直接从 `Talk.ets` 源码解析**，
  不硬编码副本 —— 见下节教训）。
- `test_name_tokenization.js` 覆盖编号规则、去重、round-trip、表格列、边界样本，
  并做过**变异测试**（把 `'学生'/'孩子'` 注回 `labels`，断言如期变红）。

## 7. 一条重要的工程教训：测试不能自带实现副本

`verify_talk_masking.js` 的 v1 版本有个隐蔽缺陷：它只在开头读了一次 `Talk.ets`，
但那份源码**仅用于几处正则存在性检查**；真正的行为复刻里，`roles`/`labels` 是
**硬编码的字符串数组副本**。

后果：实现者修改了 `Talk.ets`，脚本输出**逐字不变** —— 它测的是自己那份副本，
与真实实现完全脱钩，已经退化成"恒等于旧实现的常量"，**无法验收任何修复**。
更危险的是它看起来一直在正常工作（有时红、有时绿），不会引起怀疑。

**v2 的修法**：`roles` / `labels` / 后缀表全部从源码实时解析（`parseStringArray`），
解析失败**直接抛错退出**，绝不静默退回硬编码。

这与本项目此前踩过的"测试耦合实现写法"是同一类问题，但更隐蔽：
那次是"断言绑死某种写法"，这次是"测试自带一份实现副本"。

### 公开 API

```ts
NameMask.session(): NameMaskSession                 // 每次生成新建，结束即丢
NameMask.maskStructured(sess, value): string        // 明确是姓名的字段
NameMask.maskFreeText(sess, text, known?): string   // 自由文本
NameMask.maskTable(sess, rows, opts): TableMaskResult  // Excel 表格（按列）
NameMask.restore(sess, text): string                // 还原（只在完整文本上调用）
NameMask.applyToFlow(sess, system, user, target?): string  // fail-closed 出网闸
NameMask.isNameHeader(header): boolean
```

## 9. 给后续开发者的约定

1. **新增任何会接触学生姓名的 AI 功能**，必须经过 `NameMask`，并在页面里调用
   `applyToFlow()` 作为出网前的最后一道闸。
2. **不要把姓名拼进字符串模板**再交给 `AiService` —— 那样会绕过 `NameMask`。
   `audit_name_privacy.js` 的"全项目扫描"会自动发现这类页面。
3. **不要在流式分片上还原**编号（见 4.3）。
4. **不要给 `NameMask` 加 IO / 网络 / 日志依赖**（审计脚本会断言）。
5. 自由文本脱敏遵循"宁可漏、不可错"：宁可少脱敏（靠输入框兜底），
   也不要误改普通词汇导致生成结果错误。
