⚠️ 勘误（2026-10 更新，以本节为准）： 本图早期版本把 event 写成了 PROGRESS，这是错的 —— PROGRESS 是布局类型（LAYOUT_TYPE_PROGRESS， 用于 liveViewData.primary.layoutData），不是合法场景名， 直接传它会被华为拒收（80100003）。 实际实现按 TIMER → RENT → WORKOUT → … 依次试探 14 个合法场景， 首个成功者被记住并复用（见 LiveView.ets 的 EVENTS）。 同理，activityId 必须由客户端自己生成（Date.now() % 2147483647）—— SDK 的 LiveViewResult 只回 resultCode/message， 不含任何 id。
另：下面提到的"降级为普通通知"与"ID 三合一（= notifyId）"属早期方案， 当前实现未采用：降级路径为"静默不显示实况窗，生成照常"， 且 GenTask.ets 已注明取消消息通知功能。 进度展示的真实链路见 实况窗后台进度功能说明.md。

D关键设计约束

🔗
ID 三合一
实况窗 id = 任务 seed = 通知 notifyId。结束消息/完成通知可精确覆盖“生成中”表现；服务端只在收到上报后才发结束消息，规避对不存在 id 误发的 24h 限用。
🛡
双通道幂等收尾
进程存活：本地 stopLiveView；进程被杀：服务端 push op2 结束。两条路径重复执行无业务危害。
✅
合规边界
采用 Live View Kit 官方“进度类型 PROGRESS”，适用于用户手动开启的任务；生成由用户点击发起，符合场景定义。
📵
全链路降级
权益未审（1003500005）/开关关（1003500004）/非前台/Android 跨端 → 进行中通知；Push 未配置 → 本地通知兜底；结果永不丢失（服务端持久化+recover）。
⏱
生命周期托管
实况窗由系统渲染维护：2h 未更新隐藏胶囊与锁屏、4h 自动结束；本地创建仅要求前台，创建后与进程解耦。
🧩
文案随语言
“{type}生成中 / 已生成完成…”由 I18n 词典输出（五语言），服务端仅透传客户端拼好的本地化标题与正文。
